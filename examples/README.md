# Examples

These examples show different levels of SDD rigor. They are fictional teaching material, not client work or proof that a workflow has already shipped in production.

The three examples form a deliberate ladder. The stargazing planner is the flagship: a family-friendly question with provider contracts, external-data uncertainty, accessibility, provenance, and failure behavior underneath. The garden app is a standard application. The theatre library is a focused feature. Same discipline, different amount of paperwork. That is the point.

- [Stargazing planner](stargazing-planner/README.md) - flagship corpus for a family planning an evening outside, with configurable information providers and an explainable readiness decision.
- [Community garden and seed library](community-garden/README.md) - standard application corpus for shared plots, seeds, watering rotations, and participation rules.
- [Community theatre prop and costume library](community-theatre-prop-library.md) - minimal feature spec for reservations, condition, return, and conflicts.
- [Before and After Examples](before-after.md) - weak inputs rewritten into usable SDD artifacts.
- [Minimal CSV export feature](minimal-feature-example.md) - a small feature spec.
- [Standard team task tracker app](standard-app-example.md) - a broader app spec.
- [Rigorous payments SDK corpus outline](rigorous-corpus-outline.md) - when a full spec corpus is justified.
