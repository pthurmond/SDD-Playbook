# Community Garden and Seed Library: Standard SDD Example

A community member looks for a garden plot or seed, understands the local rules, reserves it or joins a watering rotation, then returns seed or records what happened.

This is a fictional standard-app example. It has real coordination concerns, but it does not need the flagship stargazing planner's provider architecture. The point is to show the middle of the decision ladder: enough structure for shared inventory, seasonal rules, volunteer work, accessibility, and conflict resolution, without building a municipal agriculture platform.

## What It Demonstrates

- One product can have more than one journey without losing its primary purpose.
- Seasonal rules and shared inventory are business rules, not scattered UI conditions.
- Accessible participation and volunteer ownership are requirements worth naming.
- A standard spec provides developers, PMs, reviewers, and testers a shared record before implementation begins.
